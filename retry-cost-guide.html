The Hidden Cost of AI Agent Retries

Measure cost per completed job, not the price of a single API call.

Disclosure and evidence: This educational article contains no affiliate links or paid rankings. The worked example is hypothetical. No provider performance claims are made.

Why the cheapest API request can cost more

An API request is not the unit of value when an agent needs several calls to complete one job. A low advertised price can be offset by retries, failed tool calls, timeout ambiguity and extra tokens spent recovering state. A useful comparison starts with a completed, verified task.

The metric: cost per completed job

For a defined workload and observation window, calculate total billed API spend divided by the number of jobs that passed the same acceptance checks. Include failed attempts and retries in the numerator. Exclude incomplete jobs from the denominator, but record their number separately. A provider with zero completed jobs has an undefined cost per completed job, not a cost of zero.

A worked example (illustrative, not benchmark data)

Suppose provider A bills $0.02 per attempt and completes 80 of 100 jobs after 140 total attempts. Its API spend is $2.80, or $0.035 per completed job. Provider B bills $0.03 per attempt and completes 95 of 100 jobs after 110 attempts. Its API spend is $3.30, about $0.0347 per completed job. The apparent per-attempt price advantage disappears. These figures are invented solely to demonstrate the calculation; they are not measurements of real providers.

Make task success auditable

Before running a comparison, define a fixed task set, model version, prompt, tools, concurrency and success checks. For a coding agent, checks might include test results, expected files, valid tool-call arguments and remote pull-request state. Keep a job identifier so retries and duplicate effects can be reconciled. Record latency and cost per attempt, then aggregate by job.

Retries are not always safe

A timeout does not prove a tool action failed. The agent may have created a pull request, sent a message or changed a database before the response disappeared. Inspect remote state before retrying a non-idempotent action. Treat authentication failures, rate limits and transient server errors differently; exponential backoff is not a substitute for checking whether an action already happened.

Report the limits

Separate API spend from subscriptions, taxes, human review and engineering time. Publish sample size, dates, failure counts, retry policy, workload definition and any excluded observations. Do not average batch p95 values and call the result an overall p95: raw request latencies are needed for a pooled percentile.
